# 上板与联调

[返回文档索引](README.md)

以下是按当前源码整理的检查顺序，不是本次已完成的实机测试记录。
首次接线前阅读[硬件连接](hardware.md)。

## 先明确安全条件

当前完整应用不会自动请求开启闭环，但电机自身已有上电自动回零配置的历史
记录。动力上电仍可能立即运动，必须确认当前电机配置、固定机构、留出行程，
并保留可直接断电的手段。

PA0 板载按键触发软件广播急停，不能替代独立断电措施。KEY3/KEY4 不参与
当前应用逻辑。字符调试控制台未启用，不能依赖发送 `x` 急停，也不能照旧
文档使用 `t`、`+/-` 查询或点动。

## 阶段一：不接电机动力电源

1. 检查供电、共地、SWD 和 OLED 接线，不将多个 5 V 输出直接并联。
2. 如需单独验证陀螺仪，构建并烧录[独立测试模式](../Modules/SingleAxisGyro/README.md)。
3. 该模式的 OLED 应显示 `GYRO USART3 TEST`；接收到数据后为 `DATA OK`，
   观察 YAW/RATE 随模块变化以及 `SUM ERR`、`U3E` 是否增长。
4. 数据存在只验证通信链路；角度方向、零位、量程仍需实测确认。

完整应用启动后即会尝试读取电机回零状态；不接电机或电机未响应时，机械启动
整体约 15 s 后会进入故障。因此不能要求完整应用在无电机时长期显示
`SYSTEM READY`，也不能把其故障画面直接认定为 USB 或视觉错误。

## 阶段二：USB 与视觉协议

1. 树莓派作为 USB Host，连接核心板 Type-C；查验枚举设备的 VID:PID
   `0483:5740`、产品名 `BallControl Vision CDC`。
2. 使用实际发现的 `/dev/serial/by-id/...` 路径，不照抄旧 IP 或 ttyACM 编号。
3. 在树莓派外部工程运行其黄金帧发送器，核对 MCU 协议统计及目标数据；
   发送器不在本仓库中。
4. 接入正式发送服务前，核对 V2 格式、Heartbeat 健康位和启动确认顺序，
   参见[视觉通信模块](../Modules/RaspberryPiVision/README.md)。

纯协议测试不要求电机动力上电。完整应用的机械故障可能覆盖 OLED 的视觉页面，
此时使用调试器读取接收快照/统计；单个合法黄金帧也不等于启动条件全部满足。

## 阶段三：受控检查机械启动

接通动力电源前固定机构并确认断电手段；这一步属于可能产生运动的硬件测试。

完整应用先等待约 500 ms，再轮询电机回零状态（`0x3B`）及当前位置
（`0x36`）。编码器/校准状态须就绪，不能报告正在回零或保护故障；
位置绝对值连续三次不超过 128 个电机位置单位才进入陀螺仪归零。

随后发送解锁命令、等待 100 ms、发送角度归零命令，再等待结果和连续三次
近零角度样本。不会执行零偏校准或保存参数。

整体超时、回零故障或急停会进入 `MECH FAULT`。当前机械故障状态没有运行时
自动重试入口；修正原因后需要重新启动 MCU，重启前仍要考虑电机上电运动。

## OLED 与状态含义

| 显示 | 含义 |
| --- | --- |
| `SYSTEM STARTUP` | 查看 BOARD、USB、PROTO、PI、WIFI、VISION 及底部原因 |
| `MECH STARTUP` | 机械状态页面，显示电机回零、陀螺仪归零或故障 |
| `SYSTEM READY` | 视觉启动与机械启动均就绪；不代表闭环已使能 |
| `MECH FAULT` | 机械启动失败，优先显示；可能遮住当前视觉状态 |

就绪页面的八行依次为 `SYSTEM READY`、AX/AY、IMU 帧数、ANG/W、
X/Y、IP、电机地址及 `PI START: OK`。

视觉目标达到 100 ms 未更新会变为 STALE；协议链路达到 300 ms 未更新会
变为 LINK_LOST；Heartbeat 达到 1500 ms 未更新不再满足视觉启动条件。
当前就绪逻辑要求树莓派 WiFi 健康位，即使 USB 数据通路仍在也不能忽略该位。

## 闭环启用是后续独立工作

当前源码未填写实际标定，也没有自动使能调用。要进入闭环，需完成视觉原点/
方向/毫米每像素、电机零位/方向/换算、陀螺仪方向、估计器参数及控制增益的
实测配置，再由主循环调用现有配置、设定值和使能 API。

测试文件中的参数仅用于软件断言，不能直接复制为实机标定值。本次文档与目录
整理不新增使能入口、不填写参数、不调整控制程序。
